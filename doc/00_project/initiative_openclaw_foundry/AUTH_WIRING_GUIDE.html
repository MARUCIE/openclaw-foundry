总览

openclaw-foundry 当前支持两种登陆方式，代码层已完整实现：

登陆方式前端入口代码路径需要的外部基础设施
邮箱魔法链接 /login 邮箱表单 worker/src/routes/auth.ts、worker/src/lib/email.ts、web/app/auth/callback/page.tsx Resend 账号 + API key
企业微信自建应用扫码 /login 微信扫码区块 worker/src/routes/auth-wechat.ts、web/app/auth/wechat-landing/page.tsx 企业微信公司主体 + 自建应用 + 可信域名校验文件

两种方式都签发存放在浏览器 localStorage 的 Bearer token（键 openclaw_session_token）。所有后续 API 调用（卡点墙发帖、装包下载、评论）都使用同一个 Bearer。/api/auth/config 端点会探测 worker secret 状态，把 email.enabled 与 wechat.enabled 暴露给前端，UI 在 secret 缺失时直接显示禁用按钮——不会让用户碰到 broken 端点。

当前阻塞点 → 只剩外部基础设施 + 部署
所有代码合并冲突已解决（middleware/auth、skill 页、login 页 ×2、packs 页、generate-pack-guides 脚本，加上 marketplace-shell 的类型扩展）。worker TypeScript 干净、Next.js 构建通过（12 个静态路由）。剩下的工作全部是 HITL：申请企业微信应用、注册 Resend、运行 wrangler 部署。

第一阶段 · 企业微信自建应用

选择企业微信而非个人微信网页登陆，是因为个人微信要求回调域已完成 ICP 备案。agent-foundry.pages.dev 是 Cloudflare 自有子域名——ICP 备案在结构上不可能。企业微信自建应用走的是"可信域名校验文件"流程，把一个 WW_verify_*.txt 文件放进 web/public/，由 Cloudflare Pages 在根路径直接 serve，就能完成验证。

训战群成员都有个人微信。本流程一次性的工作是 Maurice 创建公司 + 应用，然后把每位成员邀请进公司（每人 30 秒）。邀请完成后，成员用本人微信扫码即可，因为公司邀请已经把个人微信和公司绑定了。

步骤

  1. 在 work.weixin.qq.com 免费注册企业，用 Maurice 个人微信扫码注册。
  2. 管理后台 → "我的企业 → 企业信息"，复制 企业 ID（ww........... 格式），这是 worker secret WECHAT_CORP_ID。
  3. "应用管理 → 自建 → 创建应用"，名字 OpenClaw Foundry Login。保存后应用详情页展示 AgentId（数字，WECHAT_AGENT_ID）和 Secret（点击展开，WECHAT_SECRET）。
  4. 应用页 → "网页授权及 JS-SDK" → "可信域名" → 输入 agent-foundry.pages.dev。微信会给一个 WW_verify_<token>.txt 文件名和一段载荷字符串。
  5. 把 WW_verify_<token>.txt（载荷作为唯一内容）放到 web/public/WW_verify_<token>.txt。Cloudflare Pages 自动在根 URL serve public/ 下的文件，所以解析为 https://agent-foundry.pages.dev/WW_verify_<token>.txt。commit 后 push。
  6. 回到微信后台 → "申请域名校验"。微信抓取该文件一次，秒级把域名标记为已验证。
  7. 同一面板，"网页授权回调域" → 输入 agent-foundry.pages.dev。OAuth 流程的目标已写死为 /auth/wechat-landing。
  8. "通讯录 → 添加成员"，输入成员姓名 + 个人微信号。成员收到微信邀请，30 秒内可接受。

第 8 步完成后，成员用本人微信扫描 /login 页面上的二维码即可登陆——因为成员的个人微信已通过公司邀请绑定。

第二阶段 · Resend 邮件服务

选择 Resend 作为魔法链接邮件投递方案的理由：(a) 首次部署可零配置使用共享发件人 onboarding@resend.dev；(b) 定价覆盖训战群规模；(c) REST API 一次 POST 即可发送。

步骤

  1. 用 Maurice 主邮箱在 resend.com/signup 注册。
  2. 一键验证注册邮件。
  3. 控制台 → "API Keys → Create API Key"。名字 openclaw-foundry-prod，权限 Sending access（不要 Full access——最小权限原则）。
  4. 立即复制 re_… token。Resend 只会展示一次。这是 worker secret RESEND_API_KEY。
  5. （可选，上线后再做）验证自有发件域名。Resend 给 3-4 条 DNS 记录加到域名注册商。验证后设置 RESEND_FROM=login@<your-domain>，邮件就从品牌域名发出，不再使用 onboarding@resend.dev。训战群人数 ≤10 之前可跳过。

第三阶段 · 部署执行

完整命令清单见 state/openclaw-foundry-audit/auth-deploy-manifest.md。流程：

  1. npx wrangler whoami — 确认 wrangler 已登录。如返回 code: 10000，运行 npx wrangler login。
  2. npx wrangler secret put RESEND_API_KEY — 粘贴 re_… token。
  3. npx wrangler secret put WALL_PEPPER — 粘贴 openssl rand -hex 32 的输出（卡点墙匿名作者哈希盐）。
  4. npx wrangler secret put WECHAT_CORP_ID / WECHAT_AGENT_ID / WECHAT_SECRET — 依次粘贴第一阶段获得的三个值。
  5. npx wrangler d1 execute openclaw-foundry --remote --file=src/migration-v8.sql（以及 v9、v10）— 幂等迁移，如表已存在则跳过创建。
  6. npx wrangler deploy — 部署 worker，返回新的部署 ID 与 URL。
  7. git push origin main — Pages 从 main 分支自动构建。在 Pages 仪表盘观察构建成功。

每一步都可逆：secret 有 wrangler secret delete，部署有 wrangler rollback，迁移 v8/v9/v10 都是 CREATE TABLE IF NOT EXISTS，重复运行安全。

第四阶段 · 验证

bash state/openclaw-foundry-audit/verify_auth_e2e.sh

脚本探测：

  • GET /api/health 返回 200
  • GET /api/auth/config 返回 200，email.enabled=true + wechat.enabled=true
  • POST /api/auth/request 携带邮箱返回 200 + sent:true（生产环境下 delivered_via=resend）
  • GET /api/auth/wechat/start?return=/packs 返回 302，跳转到 open.weixin.qq.com 或 login.work.weixin.qq.com
  • GET /api/auth/me 无 Authorization 返回 401

脚本无法自动化的两个流程（邮箱点击、微信扫码），Maurice 需手动验证一次。两者都应该最终落在 /packs#wall 且已登录状态。

全部 5 个自动探针 + 2 个手动流程通过后，写入收据文件：

{
  echo "deploy_completed_at=$(date -u +%Y-%m-%dT%H:%M:%SZ)"
  echo "email_e2e=PASS"
  echo "wechat_e2e=PASS"
} > state/openclaw-foundry-audit/auth-deploy-receipt.txt

Goal-gate T10 检查该文件存在后才允许 /goal complete。
